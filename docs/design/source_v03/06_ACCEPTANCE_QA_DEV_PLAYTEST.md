# V0.3 Codex 验收规范：剧情、俄语、找猫、整理、手账与存档

状态：拟纳入正式 Codex 任务卡的验收草案；**测试内容已定义，但尚未有游戏可运行，因此不存在游戏实测 PASS**。

## 1. 项目要求

- 每次交付提供 Git SHA、实际运行命令与结果、关键浏览器截图/录屏、已知缺陷和 3 个以上设备视口的验证记录，不得用 TypeScript 编译通过代替用户真实试玩。
- PC 1440×900；移动端 390×844、360×800，找猫附测 360×780。触摸控制、文字换行、遮挡与不同 DPR 需要检查。
- DEV、PLAYTEST、RELEASE 共用相同业务规则实现，但构建与存档命名空间不同；正常试玩、首次重玩回归绝不能因 DEV 强制跳任务而被覆盖。
- PLAYTEST 至少具备「正常新档试玩」与另行隔离的「开发者专项测试」方式；不能在正常玩家 HUD 隐藏一套可被任意打开的作弊面板。

## 3. 静态数据验证（Codex 后续必须实现）

1. 每个 `dialogueId`, `speakerId`, `localizationKey`, `vocabId`, `roomObjectId`, `rewardKey`, `puzzleId` 均可解析到相应配置；无重复 ID。
2. 每条正式 NPC 俄语文本均含对应中文字幕；地图标签有中文与俄语，不把中文固定画在贴图上。
3. 每个藏点的提示位置、俄语词汇、路径、前景遮挡层与对象 ID 均存在；四个点均有效。
4. 每道谜题容量为正、物品占用量为正、约束引用的物品与仓位实际存在，并通过可解性枚举或 SAT/约束检验。
5. 游戏运行逻辑不能调用 JSON 文件中的 `verification.exampleSolution` 作为单一判题依据；验收时检查一题多解。
6. `grantOnce()` 对首次猫咪、首次整理、每日本地日历印章去重，重复派发事件不得修改原始奖励账本。
7. 场景大小、不同视口安全区和地面/镜头变换不应让关键点击热区变得不可操作。

`fresh_start`, `before_first_cat`, `cat_bed`, `cat_window`, `cat_wardrobe`, `cat_desk`, `cat_answered_not_petted`, **`cat_petted_name_pending`**, `cat_named_before_org`, `before_org_tutorial`, `org_daily_03_solution_a`, `org_daily_03_solution_b`, `org_same_day_replay`, `org_next_day`, `before_city_unlock`, `before_school_pickup`, `chapter01_completed`。

每个预设必须使用测试专用存档命名空间，预设只是快速填入**合法**业务状态，不允许绕过存档不变量制造不可恢复的主线状态（专门测试非法数据迁移时例外）。

## 5. 通过状态

- `SPEC_READY`：设计内容与数据合同具备实现所需边界（不代表游戏已完成）。
- `FUNCTIONAL_DEMO_PASS / ART_PENDING`：交互、剧情、存档、QA 全部符合，但仍使用临时资源。
- `FINAL_DEMO_PASS`：功能验收之后另完成正式美术、性能、版权/发布就绪检查。当前阶段不启动最终发布手续。

用户实际试玩和明确确认是最终接受某个功能的必要步骤；QA Agent 不能用自述取代真实证明。
