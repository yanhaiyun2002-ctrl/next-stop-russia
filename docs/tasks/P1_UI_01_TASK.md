# 《下一站，俄罗斯！》P1-UI-01｜全屏场景、城市地图交互与游戏 UI 美术统一整改

## 一、任务背景与正式授权

负责人已经试玩 P1 正式整理玩法与圣彼得堡主地图整合版本。

目前需要解决的不是玩法，而是整体界面缺乏游戏美术表现的问题。

主要反馈：

1. 游戏经常出现大面积黑边、黑色底框或深色容器，场景没有真正铺满画面。
2. 地图建筑缺少直接可见的地点标签，玩家不知道哪些建筑可以互动。
3. 点击建筑后的黄色轮廓需要更自然的正式选中反馈，不能像调试碰撞框。
4. 当前按钮、菜单、对话框、任务提示等 UI 仍过于生硬，和已经使用的 AI 场景美术及圣彼得堡地图不协调。

**本轮批准同步进行全屏视觉修复、UI 美术资源制作、地图标签与选中效果优化。**

不是重新制作游戏，不是重设计玩法，也不是进入新剧情开发。

工作目录：
`E:\俄语游戏\NEXT_STOP_RUSSIA`

技术基线：
Godot 4.7.2 Stable，GDScript，Compatibility，唯一正式工程。

## 二、UI 美术方向

采用“温暖旅行手账＋轻插画游戏 UI”作为本阶段统一设计方向。

主要特征：

- 温暖米白色纸张或奶油色半透明底板。
- 浅金、浅棕边框和柔和阴影。
- 深蓝灰色文字，局部采用低饱和绿色或金色强调。
- 细致圆角与温和的按钮按下反馈。
- 适当运用旅行便签、纸张、地图标牌等装饰元素。
- 俄语与中文排版清晰。
- UI 轻量化，不遮挡场景插画主要内容。

不要采用：

- 大面积纯黑或近黑色矩形面板。
- 默认 Godot 灰色或绿色测试按钮。
- 厚重 RPG 金属框、复杂奇幻游戏 UI。
- 像素风 UI 与非像素插画混搭。
- 过量装饰、无意义的动画或复杂视觉特效。

允许依据实际场景适当微调，但必须形成一套统一的视觉体系。

此次属于 RETAIN_CANDIDATE 级别的视觉设计，不代表全部最终发行美术已永久批准。

## 三、优先使用已有美术生成能力

请检查现有项目级：

`.agents/skills/game-art-pipeline/SKILL.md`

以及已验证可用的官方 imagegen Skill。

优先使用已有内置图像生成能力，为本轮 UI 制作少量必要的原创资源。

需要的资源优先包括：

1. 可伸缩对话面板和信息卡片。
2. 按钮正常、悬停、按下、禁用状态。
3. 地点名称标牌与锁定状态图标。
4. 小型任务提示、消息、返回、继续等通用控件装饰。
5. 建筑选中反馈需要的轻量美术元素。

允许参考 Kenney UI Pack：

https://kenney.nl/assets/ui-pack

但必须先审查真实资源包的许可证、格式、风格及可缩放性。

如果 Kenney 的默认素材与当前插画画风不协调，优先使用原创生成资源或 Godot Theme 绘制，不要为了使用第三方素材而牺牲整体统一性。

无需购买软件、申请付费 API 或安装大量新工具。

如 Codex 内置 imagegen 仍可用，直接调用；如不可用，明确记录限制并使用已有资源及 Godot 原生主题能力。

不要把 AI 生成的整页 UI 效果图当成可交互控件。

## 四、建立统一游戏 UI 主题

不要每个场景自己硬编码一套颜色、按钮和背景。

请建立或扩展小规模共享的 Godot UI Theme、StyleBox 和通用组件。

优先使用：

- Godot Theme。
- StyleBoxFlat。
- StyleBoxTexture。
- NinePatchRect 或等价的九宫格资源。
- 现有 Control 布局与响应式锚点。

集中管理：

- 面板样式。
- 按钮状态。
- 标签与字幕样式。
- 间距、圆角、阴影。
- 常用图标。
- 横竖屏字号和触摸尺寸。

必须确保俄罗斯语西里尔字符和中文同时正常显示，字体许可证与字符覆盖需检查。

文本、任务内容、地点名称、按钮状态必须通过 Godot 控件和现有数据渲染。

不允许把会变化的文本和交互状态烘焙到背景图片中。

不建立复杂的全新 UI 框架；优先改造现有组件。

## 五、修复全游戏无意的黑边

先检查实际根因：

- project.godot 的窗口与 stretch/aspect 设置。
- 各主场景根节点锚点。
- UI 外层容器和 padding。
- 背景缩放模式。
- Control 裁切与安全区域。
- 地图背景的缩放和平移。
- PC 和手机逻辑画布与实际视口的匹配方式。

特别区分：

1. 真正的视口 letterboxing。
2. 图片 contain 留边。
3. 场景外套了深黑色 UI 底板。
4. 背景没有覆盖到窗口边缘。

不能仅把黑色换成浅色来掩盖问题。

目标：

- 场景背景铺满有效视口。
- 保持正确的图片宽高比。
- 必要时少量裁切或允许受控浏览。
- UI 在安全区域内，背景仍覆盖整屏。
- PC 横屏和手机竖屏都不能出现无意义的大面积黑框。

需要检查的场景：

- 圣彼得堡主地图。
- Q00 开场剧情。
- 宿舍及猫咪互动。
- 正式 Q02 整理。
- Q03 消息和必要的主线导航界面。

对于整理等功能界面，允许使用小面积设计面板，但不允许整个窗口外包一个厚重黑框。

对于背景本身需要遮挡或暗化的剧情演出，保留合理的戏剧性暗化，不把有意的场景效果错误清除。

## 六、圣彼得堡地图 UI

保留：

`docs/art-source/city_map/city_map.png`

及运行时：

`assets/city_map/st_petersburg.png`

不得重画、覆盖或修改负责人原图。

地图 UI 必须体现地图本身的城市插画美感。

### 1. 建筑标签

当前三个配置地点：

- dormitory：宿舍。
- school：大学。
- shop：商店。

依据 `data/city_map.json` 中已有的负责人指定区域。

为地图上的对应建筑添加清晰的常驻标签或标记。

要求：

- 玩家不点击也能识别地点。
- 标签在建筑上方或附近，通过短引导线与建筑对应。
- 标签使用暖色手账风格，而非深黑色方框。
- 俄语主名称、中文辅助名称可以共同显示。
- 复用现有地点数据和本地化内容。
- 标记数量目前只限已配置的三个地点。
- 锁定地点也能显示名称及锁定状态。
- 点击标签和点击建筑使用相同的导航／选择逻辑。
- 不自动开放学校或商店。
- 不让标签大面积遮挡建筑主体。
- 标签随地图缩放和平移同步。

地图可以保留一个轻量地点列表或任务定位入口，但不能强制玩家依靠底部列表猜测建筑位置。

### 2. 点击后的黄色高亮

查明当前黄边来自：

- 调试多边形描边。
- Godot 控件焦点框。
- 真实选中状态效果。

最终要求：

- 未选中时没有粗糙的黄色调试轮廓。
- 点击建筑或标牌后，有协调的暖金色反馈。
- 标签同步选中。
- 允许使用柔和光晕、轻量轮廓或小型位置标记。
- 如果无法可靠贴合建筑轮廓，不要拿粗糙的点击热区多边形冒充建筑描边。
- 点击空白处、切换地点、退出时状态正确清除。
- 锁定地点只能显示锁定说明，不能进入。
- 缩放、拖动及横竖屏下反馈位置保持正确。

不要求把整张地图切成独立建筑图层。

### 3. 地图全屏与浏览

PC 横屏尽量完整表现地图，以等比 cover 为主要目标，避免明显留边。

手机竖屏用等比例铺满和受控地图平移，允许浏览整张城市。

保留原有缩放、任务定位和地点导航。

点击标记与拖动地图必须正确区分。

### Q00 剧情

保留已有场景美术、安娜与管理员、俄语主对白＋中文字幕。

重点改造：

- 双语对话框的背景和边缘。
- 继续按钮。
- 说话人标签。
- 手机竖屏布局。

保留现有对白和角色资源，不重写剧情。

### 宿舍

保留现有镜头、横向浏览、家具交互和找猫系统。

重点改造：

- 返回城市按钮。
- 整理、消息等功能入口。
- 左右浏览箭头。
- 家具俄语标签底板。

目前宿舍部分旧几何家具仍属于 MUST_REPLACE，但本轮不重做宿舍家具美术。

### 正式 Q02

现有长短排序＋共边对齐玩法已经批准保留。

本轮只允许小范围视觉样式统一：

- 返回／退出。
- 转向。
- 撤销、重来。
- 提示和完成按钮。
- 相关信息面板。

不得改变已经认可的拖放、旋转、吸附、判定和存档逻辑。

不增加新物品、题目、关卡、每日任务或额外动画机制。

### Q03 和其他必要导航

使用统一的纸张式消息卡、返回按钮和简单导航样式。

不增加剧情内容，不改动已确认俄语和中文字幕。

## 九、研发流程

这轮允许直接完成 UI 设计、必要资源生产和 Godot 集成，不需要拆成多次独立开发阶段。

但请依次进行：

1. 审查现有 UI、黑边和地图交互根因。
2. 制作统一的 UI 视觉规范与少量独立组件。
3. 优先改造地图，确认整体风格。
4. 将相同主题应用到 Q00、宿舍、Q02 和 Q03 的必要控件。
5. 检查 PC／手机真实运行效果。
6. 修复本轮引入的布局、点击和字体问题。

不要大规模生成图片。

如果生成结果不满足独立控件、透视、alpha 或清晰度要求，可以回退使用 Godot Theme 绘制，不能为了坚持图片生成而留下更差的 UI。

生成的视觉资源属于 RETAIN_CANDIDATE，供负责人最终审查。
