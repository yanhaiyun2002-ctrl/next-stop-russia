# P1-01 正式开发任务｜第一段完整可玩体验

## A. 任务范围与授权

**目标：** 在现有 Godot 4.7.2 + GDScript + Compatibility 主工程中，制作一段以既定 V0.3 剧情 Q00～Q03 为骨架的 First Playable，玩家能开始、连续体验、保存、退出恢复和自由重玩找猫。**不重复 P0 技术原型，不重新策划流程，不另建一套游戏。**

**用户已确认的顺序不可改变：** 安娜/管理员→进宿舍→首次猫完整 R3.2→首次整理教程→安娜消息→城市开放。不得用“先整理再找猫”的临时建议覆盖 V0.3。

## B. 首要执行（仅最低限度工程检查）

1. 读取根目录现行 `AGENTS.md` 与本包的决策、差异、任务和 E 盘规则；按需读 `source_v03/`。不重做旧 R0 审计或 P1-00。
2. 执行 `git status --short --branch`、`git log -1 --format=%H`、`git worktree list`，检查现有 P0 测试入口和 `.tools/` 目录；如发现工作区未提交改动，保护并报告，不自动覆盖。
3. 复用现有 P0-01～P0-04 的 Godot 场景、建筑 ID、找猫技术、家具遮挡、横拖、原有 test 套件。仅做所需最小接口增量。
4. 遵守 E 盘优先、不得未经授权安装体积巨大的软件；已存在 Android SDK/JDK/Godot 便携包不重复下载。

## C. 建立最小可靠的领域状态（先冻结合同）

不搭完整通用 MVC、引擎或万能小游戏 Host。只建立本轮确实需要的版本化轻量状态，采用适合 Godot 的原生 Resource／字典／JSON 与必要的 GDScript 服务：

- `Quest`: Q00～Q03 的 `locked/active/completed`；`hasHomeKey`、`cityUnlocked`。
- `Cat`: 稳定品种 ID、首次摸猫、`namePending`、`displayName`、首遇奖励一次、自由找猫状态。
- `Organization`: tutorialCompleted，当前教程的本地状态；本轮**不必开发**完整自然日轮换日历。
- `Reward ledger`: 同一 rewardKey 重复处理只发一次；不引入金币。
- `Save`: schemaVersion + 可靠读写、备份/坏档恢复策略、DEV/PLAYTEST 不同物理存档或不同路径；未见存档前先用一次迁移版本规划。
- `Content`: 使用 ID 对应的剧情对白、俄中字幕、家具俄语词、教程题；独立于渲染脚本。

领域关键事件遵守 `cat.pet_reaction_completed` 奖励和 `cat.name_confirmed` 推进 Q01 的分离；城市解锁只能在 Q01/Q02 完成后。

## D. 第一段连续流程 Q00～Q03

**Q00 安娜与管理员**：简洁、可读的俄语主台词＋中文字幕；交房间钥匙并进入宿舍；优先复用 `source_v03/01_MAIN_STORY_NPC_RU_ZH.md` 草案，标 `TEMP_TEXT`。跳剧情演出不跳关键条件，不新增第三正式 NPC。暂用文字牌/剪影，不要求角色最终立绘。

**Q01 首次完整找猫**：保持猫先可见，并采用可见的连续移动／探头／出场／摸猫简化补间；四处藏点为床、窗、柜、桌（需补当前缺的窗位），不能完全不可见或只能通过 debug 才点到。家具附近俄语标签首次中俄双语，正确家具标签的同一次交互尝试朗读并判定；如果俄语音频资源不存在，使用非阻断且状态可解释的静音文字回退，**不能在没有真实音频的情况下假称已播放**。错选不处罚、不换点。正确后猫从家具位置连续出来，等待玩家点击摸猫，**摸猫反应完成**发一次性首遇奖励，再弹出**不可跳过但可在下次启动恢复**的命名确认。确认名字才 Q01 完成。可反复找猫的原功能保留，并跟首遇状态区分；原三处位置短句可作为自由模式内容，不替代家具标签玩法。

**Q02 首次整理教程**：通过宿舍**独立侧边「整理」按钮**进入，不绑定任何家具入口。优先使用 V0.3 `organization_templates.v1.json` 的教程样题。验证全部物品放置、格位容量、合法仓位、禁止共仓等已有题目用到的约束。玩家可选择/放置/撤销/重置/确认；有效解法都通过（不能只接受唯一示例），可以退出再进入而不会令剧情不可恢复。奖励为首次纪念/手账记录，不增加货币和永久大型装修系统。

**Q03 安娜消息与城市解锁**：俄语主消息＋中文字幕；只在 Q01/Q02 完成后解锁城市，完成时记 `story.city_unlocked`。保持现有技术地图可进入宿舍/学校、商店锁定，但在首日流程未完成前按剧情合同限制出门；DEV 模式可以直接进入技术地图验证既有导航。P1-01 不建正式圣彼得堡六入口，不实现大学领资料 Q04/Q05。

**First Playable 结束：** 给玩家明确完成首段的反馈，然后允许自由进入宿舍找猫、从地图返回等；不把可重复找猫变成固定关卡。

## E. TEMP 美术与操作体验

- 允许小规模原创占位：宿舍墙/地/顶/窗分层、必要家具、猫简易可动图层、NPC 剪影/文字牌、对话与命名/收纳/反馈 UI；依据 `docs/design/TEMP_ART_GUIDE.md` 的合同记录 `TEMP_REPLACE_REQUIRED`。
- 不要求本轮全部绘制正式插画；优先让 First Playable 在手机竖屏和 PC 横屏不需要开发者提示就可理解操作。默认隐藏旧测试面板。
- 不自行改变 P0-03R 的宿舍主视觉方向；后续轻俯视等待制作人单独审美批准。
- 美术参考与生成图不自动获得游戏使用授权；不要把原参考视频、旧 WorkBuddy 图、未获许可网络素材打包。

## F. 测试计划和必须覆盖的异常

保留 P0 导航、房间空间/构图、横拖和自由找猫测试原有正确性合同；确实不适用的旧断言必须有解释及等价回归，禁止直接删除/降低断言。

新增：
1. 从新档 Q00→Q03 完整连续游玩，不通过 DEV 跳状态；俄 NPC＋中文字幕正确。
2. 四个藏点都有可见证据，家具 ID/词汇标签/猫锚点一致；错误不惩罚、不换位；正确后连续走出、摸猫反馈。
3. 首次摸猫前退出无奖励；摸猫后命名前退出可恢复、领奖仅一次；确认名字才能 Q01 完成。
4. 简单整理题至少存在一解，非法摆放会失败且能撤销；合法多解均可通过；退出和重进不会跳过 Q02。
5. 首次城市解锁条件正确；不能跳字幕绕过 Q01/Q02；自由找猫能连玩 10 次以上；不重新强制命名。
6. DEV/PLAYTEST 存档互不污染；坏档恢复/文件版本显式记录，禁止隐式清除用户进度。
7. PC 横屏/模拟手机竖屏点击与横拖不会互相误触；已知 P0-04 首轮触摸 9 失败仍开放，必须测回归并记录是否复现。
8. Godot 主入口、既有导航、Windows 实际渲染真实运行；有设备则 Android 真机验证，没有则标未测。缺少真人试玩不能宣称玩法趣味已经通过。

## G. Agent/Worktree 与报告

优先主 Agent 统筹、独立 QA；只在界面/领域接口冻结且允许文件不重叠时开 E 盘 Worktree。每张实做任务记录 owner、allowedPaths、baseSHA、测试计划。不得改旧工程核心资源 ID、删除历史 Git 或建立远程。

最终项目本地输出 `docs/reports/P1-01_SUMMARY.md`，整合真实成果、文件/数据变化、命令、逐项测试及失败、试玩路径、TEMP 资产清单、Git commit SHA、待用户决策项。所有原始日志与截图存本地 E 盘。Codex **不需要把多个报告逐份上传**；主线只收一份汇总，出现视觉争议时再合成一张对比图。
