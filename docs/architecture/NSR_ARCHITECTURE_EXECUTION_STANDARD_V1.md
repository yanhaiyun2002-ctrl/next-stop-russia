# 《下一站，俄罗斯！》开发架构执行标准（NSR-ARCH-STD-01）

**版本：** V1.0 · 待制作人确认并纳入工程后执行  
**适用范围：** 唯一 Godot 主工程的所有后续功能开发、修复、重构、资源接入、数据迁移、测试与 Codex 子代理协作。  
**技术基线：** Godot 4.7.2 Stable / GDScript / Compatibility；PC 横屏、手机竖屏；DEV／PLAYTEST／RELEASE 隔离。  
**架构：** 模块化单体 + 数据驱动内容 + 最小活动契约 + 统一领域状态事务。  
**当前状态：** 架构约束文件；**不是**实施 ARCH-02 或开发 Q04/Q05 的授权。

## 1. 权限、效力与冲突处理

1. **制作人是唯一架构例外批准人。** Codex、子代理、自动测试或其他 AI 无权自行批准架构越界。
2. 规范效力顺序：**制作人最新明确决定 > 本执行标准及制作人批准的架构变更记录（ADR） > 已批准的模块契约和任务卡 > 现行产品决策与设计交接 > 历史规划和既有实现。** 如果条款冲突、含义不清或某项资料仍为 PROPOSED，先标记冲突并向制作人申请；不得自行把草案升级为既定事实。
3. 本规范约束**所有新增和修改的代码**。当前工程已存在的跨模块耦合可暂时运行（见第 9 节）；不得以“旧代码就是这样”为由扩大耦合，也不得为了形式整洁未经授权进行全局重写。
4. 任何开发任务都必须有 **任务 ID、目标、允许修改路径、禁止修改路径、受影响模块、测试范围、停止条件**。未列入的路径一律视为未经授权。
5. 本项目 ChatGPT 对 GitHub **只读**；GitHub 上的提交、推送、分支管理和写入由制作人授权的 Codex 执行。不要请求 ChatGPT 代替 Codex 写入仓库。

## 2. 不可突破的架构红线

**禁止：**

- 功能模块直接读写其他模块的私有字段、内部节点或存档子树；尤其禁止通过 `session.state.foo = ...` 修改进度、奖励或跨模块数据。
- UI、地图热点、猫咪动画或活动画面直接发放奖励、解锁城市、完成其他模块任务；所有永久状态必须进入**统一合法领域命令与存档事务**。
- 地图、学校、找猫、整理等模块互相 `get_node()` 查找内部节点、直接实例化对方的内部视图，或调用对方未公布的私有方法。
- 把不同功能的逻辑继续堆入 `scripts/main.gd`、`scripts/p1/flow.gd`、`scripts/p1/session.gd`，或新增万能 Manager、万能 Autoload、全局 EventBus。
- 直接依赖其他模块的场景节点层级、视觉像素坐标、未稳定的资源文件名，作为剧情或存档的业务 ID。
- 在没有批准的迁移设计时修改存档结构、删除兼容字段、变更稳定 ID、重置已有存档；不能为了“简化”移除备份、失败回滚或未来版本拒写。
- 把 DEV 预览、测试 fixture、作弊入口带入 PLAYTEST／RELEASE，或混用三种模式的玩家档。
- 用历史旧方案覆盖现行决策：禁止复活 React/Phaser 工程、旧 A/B/C 整理玩法、固定猫咪关卡体系。
- 未经制作人授权扩展任务范围、修改无关文件、合并高风险重构、发布新内容或进行强制 Git 历史改写。

**允许的跨层使用：** 通过已批准的公开契约、只读数据视图、显式请求/结果、Godot 信号和上层协调器进行通信。这属于正常模块协作，**不属于越界**。但修改共享契约本身必须走第 6 节审批。

## 3. 模块职责与代码所有权

下表是**逻辑所有权和现有路径映射**，不是要求立刻迁移全部目录。后续任务卡应将实际文件精确归属到唯一主责模块。

| 模块 | 现有主要路径 / 未来建议 | 允许职责 | 禁止职责 |
|---|---|---|---|
| **Application / Navigation** | `scripts/main.gd`；未来可增 `scripts/app/` | 启动、场景生命周期、地图／房间导航、活动装配、输入焦点、返回与恢复 | 猫咪规则、整理判题、课程评分、直接结算奖励 |
| **Story / Progression** | `scripts/p1/session.gd` 的现行领域入口；未来独立故事规则与事务处理 | 主线门禁、任务状态、领域命令、奖励幂等、NPC 关系里程碑 | 创建对话控件、操作宿舍内部节点、实现小游戏规则 |
| **World / Locations** | `scripts/map.gd`、`ui/map_board.gd`、`scripts/dormitory/`、`data/buildings/` | 稳定地点 ID、地图锚点、建筑选择、宿舍世界坐标、镜头、热点与场景显示 | 直接改变任务进度、直接发奖 |
| **Pet / CatCompanion** | `scripts/p1/cat_encounter.gd`、`scripts/p1/home_controller.gd` 的猫咪部分 | 四藏点、识词、猫咪运动／摸猫、无限重玩、宠物瞬态交互 | 控制整理、学校或地图解锁；以关卡制取代自由互动 |
| **Activities / LuggageTidy** | `scripts/p1/luggage_tidy/`；未来 `scripts/features/<id>/` | 自身规则、交互、活动内存、活动开始/结束结果 | 直接修改其他模块状态或自行推进剧情 |
| **Content / Localization** | `data/p1/`、`data/city_map.json`、`scripts/p1/content.gd`、设计交接 | 已批准的剧情/俄中双语/词条/地点数据和静态引用校验 | 无验证动态执行任意脚本、把草案当终稿 |
| **Persistence / Runtime** | `scripts/p1/save_store.gd`、`profile_catalog.gd`、`runtime_mode.gd` | 存档读写、备份、恢复、schema、档位、模式隔离；领域数据校验应分离 | 加载实际 UI 场景、决定猫咪或课堂玩法规则 |
| **Presentation / Assets** | `ui/`、`scripts/p1/story_stage.gd`、`scripts/p1/art.gd`、`assets/art_registry.json` | UI Theme、显示、输入呈现、资源映射、视觉与响应布局 | 持有永久任务规则、奖励写入权限 |
| **Dev Tools / QA** | `scripts/dev_tools/`、`tests/`、`scripts/dev/` | 隔离预览、合法 fixture、回归、打包审计 | 写入玩家真实存档、在正式包注入调试后门 |

**约束：** 同一文件若目前同时承载多个职责，标记为 `LEGACY_MIXED`；本轮仅在允许范围内抽取，未获批准不得跨多个业务模块同时改造。共享文件如 `project.godot`、`scenes/main.tscn`、`AGENTS.md`、`assets/art_registry.json`、存档 schema 和模块注册表由**指定单一集成人**串行修改。

## 4. 模块通信规则（唯一合规路径）

1. **入口：** 应用层用稳定 `featureId`／`activityId`／`locationId` 及经过验证的上下文启动模块。场景内部 UI 不读取全局目录扫描结果并任意动态执行脚本。
2. **模块内：** 功能自身管理玩法规则、表现和非持久临时状态；只读取自己被授予的上下文或公共只读数据。
3. **输出：** 模块通过明确的信号或返回值报告 `completed`、`cancelled`、`interrupted`、`failed` 等结果，以及必要的稳定结果 ID；不得在输出回调中直接操作另一个功能的私有状态。
4. **结算：** Application/Story 将结果转为已定义的领域命令；Session/StateTransaction 检查前置条件和幂等键，成功持久化后再宣布永久进度改变。
5. **展示：** UI 通过只读 ViewModel/状态快照呈现，或调用明确授权的命令；不私改存档字典。
6. **导航：** 由 Application 统一控制进出场景、焦点、触摸取消和返回，不允许子模块偷偷改变主地图导航状态。
7. **共享数据：** `questId`、`eventId`、`activityId`、`locationId`、`assetId`、`dialogueId`、`spotId`、`vocabId` 应稳定、唯一、可校验；更名必须提出兼容策略。

### 活动结果最小示例（契约示意，当前并非已部署 API）

```json
{
  "activityId": "luggage_tidy",
  "sessionId": "unique_activity_run_id",
  "status": "completed",
  "resultId": "luggage_tidy:first_completion",
  "payload": {"validArrangement": true}
}
```

`status` 可以是 completed / cancelled / interrupted / failed；重复投递同一结算结果不能重复发奖。猫咪不必继承统一关卡基类，但首次摸猫与命名结果同样只能通过公开的故事进度入口结算。

## 5. 新增／修改／删除功能的操作标准

### 新增功能

- 在开发前写清：功能所属模块、稳定 ID、输入/输出、内外状态、是否持久化、主线是否依赖、运行模式与可访问入口。
- 优先新增自身目录和内容配置，仅修改**一个声明清晰的装配／注册入口**和必要的公开契约；不得为新学校模块修改找猫和整理内部实现。
- 新增学校学习系统之前，Q04/Q05 首次到校与领取资料属于剧情/地点功能；完整课堂活动必须另有批准的玩法方案。不得预建大规模考试、课程表、AI 评分、体力或经济系统。
- 新模块在 DEV 可隔离预览，PLAYTEST/RELEASE 中只暴露已批准入口；增加模块测试与跨模块回归。

### 修改已有功能

- 默认仅改该模块 owned files 和任务卡白名单；外模块只允许调用**已批准的公开接口**。
- 涉及公共 UI、资源或地图等共享文件时，任务卡必须提前列出修改理由、唯一文件 owner 和兼容测试；否则先申请。

### 禁用或删除功能

- 先解除入口／注册，评估任务前置、旧档（已完成和进行中）、奖励及资源依赖；有主线强制依赖则必须提出替代流程并经制作人批准。
- 在兼容校验通过前，不能直接删除活动快照的读取逻辑，也不能静默抹掉旧档未知但受支持的数据。
- 禁用测试必须确认无悬空资源、无非法入口、DEV/PLAYTEST/RELEASE 均可正常启动和返回。

## 6. 跨模块变更申请机制（强制阻断门）

出现**任一**情况，Codex 必须**立即停止相关实现，只进行必要的只读分析并向制作人提交申请**：

1. 必须修改任务卡白名单外的源文件，尤其是另一个模块的内部实现。
2. 必须修改任何共享契约：模块公开入口/事件语义、任务/地点稳定 ID、全局注册规则、公共 UI/布局协议。
3. 必须新增或改变存档 schema、迁移规则、奖励去重、任务解锁或三模式权限边界。
4. 必须绕过现有分层才能完成目标，如 UI 需要直接写另一模块的状态、活动需要访问宿舍内部节点。
5. 必须采用重大工程结构调整、引擎升级、资源批量搬迁、跨业务模块重构，或修改主分支的已批准行为。
6. 任务需求与已批准架构、产品决策冲突，或无法确定数据归属。

**申请格式（必须完整）：**

```text
[NSR 架构越界／契约变更申请]
任务 ID：
当前 Git SHA / 工作分支：
当前所属模块：
需要触碰的其他模块／文件：
当前规则或公开接口：
必须越界的具体原因（附调用链和证据）：
方案 A：不越界的最小替代方案（含代价）：
方案 B：请求变更的接口／边界（含收益）：
对剧情、旧存档、奖励、三模式、PC/手机的影响：
需要修改的精确文件白名单：
测试与回滚计划：
申请制作人决定：批准 A / 批准 B / 拒绝 / 另行指定
```

**只有制作人明确回复批准具体方案和文件范围，Codex 才可继续相应改动。** 沉默、测试通过、子代理同意、文档里出现 PROPOSED、已有历史坏例子均不构成授权。批准仅对该任务和列明的文件范围有效；扩大范围须重新申请。被拒绝则保留现状并停止，不擅自绕行。

**例外：** 只读调查、失败复现、隔离测试记录不视为代码越界；但不得借“诊断”修改其他模块的正式运行文件。紧急存档故障也不能跳过制作人批准，允许先采取不修改用户档的只读保全和风险报告。

## 7. Codex 每项任务必须遵守的工作流程

**开工前（Preflight）：**

1. 读取本标准、根 `AGENTS.md`、最新有效产品决策、对应模块契约、任务卡以及本次涉及的真实源码；核对当前 Git 分支/SHA、未提交更改。
2. 输出一份简短的 **任务边界表**：本次目标、owner 模块、允许修改路径、只读依赖模块、接口调用、潜在存档/模式影响、测试、停止条件。
3. 如需要越界，**先提交第 6 节申请，不写入越界源代码**。未列明的任务不能自行补做。

**开发中：**

4. 模块内部优先完成；新依赖应通过现有公开接口，不允许访问其他模块私有变量/节点；尽可能保持单一状态所有者。
5. 发现实际需要修改白名单外文件时立刻暂停相关工作，不能“先修完再报告”。
6. 不改用户实际存档，不执行 reset --hard、clean -fd、强推或未经授权的历史重写。多代理工作时共享接口只有一个 owner，其他代理只读等待。

**提交前（Verification）：**

7. 展示 `git diff --name-only`，逐文件对照白名单；任何超范围改动都需撤销**本任务新改动**或先申请，不能误丢用户原有修改。
8. 运行本模块单测及相关跨模块回归；涉及主线/存档须覆盖 Q00→Q03、旧已完成/中途档、失败回滚、奖励幂等、损坏恢复、未来 schema 拒写；涉及场景/UI 须验证 PC 横屏和模拟手机竖屏；涉及打包须审计三模式资源边界。
9. 测试必须注明真实执行结果；headless、模拟触摸、Android 构建和真人真机体验不可互相替代。
10. 交付包含 SHA、变更文件、架构边界检查、测试结果、遗留风险。完成任务后停止，不自行进入下一阶段。

## 8. 静态保护和门禁（建议在 ARCH-02 后逐项落地）

- 为模块提供 `module_owner` 文件清单／任务卡 `allowedPaths`，提交前检查差异并阻止无授权的越界文件更改。
- 增加引用扫描：禁止业务 UI 中直接修改 `P1Session.state`；禁止玩法内部读取另一个玩法的私有路径；检查新 Autoload、动态 load 路径和全局状态写入。
- 验证内容数据：重复 ID、失效 `dialogueId`/`vocabId`/`locationId`、中俄字幕缺失、地点场景引用失效。
- 单独测试活动启动/完成/退出、信号断连、释放节点、返回焦点、重复结果幂等与模块禁用；再做三模式打包审计。
- 对历史代码和受批准的适配层采用**具体路径／原因／迁移任务号的白名单**，不使用全局忽略或仅靠提示词自称通过。

**注意：** 本标准是流程约束；若需 Git/CI 机械性阻断，必须由 Codex 在后续获授权任务中实现相应守卫与检查。本文件本身不会自动拦截代码变更。

## 9. 已发现的历史耦合与迁移规则

以下是读取当前 `main` 的实际代码所得事实，现阶段标记 `LEGACY_MIXED`，**不是立即全量重写授权**：

- `scripts/main.gd` 同时承担启动、建筑 CATALOG、剧情初次入口、档位和 DEV 装配。
- `scripts/p1/flow.gd` 同时创建对白／命名 UI、控制剧情步骤、操作地图任务和房间返回。
- `scripts/p1/home_controller.gd` 管理猫咪 HUD 且将宿舍 `room_view` 重挂载到主入口。
- `scripts/p1/cat_encounter.gd` 同时持有房间世界、房间镜头和 Session。
- `scripts/p1/luggage_tidy/view.gd` 直接调用 Session 的空间保存及 Q02 完成。
- `scripts/p1/session.gd` 混合 Q00–Q03、猫咪命名与奖励、整理进度。
- `scripts/p1/save_store.gd` 在读写器中同时校验故事／猫咪／整理和旧分仓数据。

迁移次序建议：**ARCH-02 领域命令与存档校验边界 → ARCH-03 剧情呈现/导航生命周期 → ARCH-04 最小活动契约 → ARCH-05 地点注册与内容校验 → ARCH-06 DEV 模块增删验证。** 每阶段独立任务、分支、回归和制作人验收；不得因使用此文档自动执行这些阶段。

## 10. 最终架构合格标准

- 新增学校模块无需触碰找猫、整理内部文件。
- 修改整理规则不影响地图、猫咪和存档外层读写逻辑。
- 猫咪可自由重玩，不被强行套入固定关卡接口。
- UI 不能越权提交奖励；任务完成由合法领域事务提交，失败不变更永久进度。
- DEV 里能注册、启动、退出、禁用一个测试活动，且 PLAYTEST/RELEASE 正常流程不受影响。
- 旧存档、未完成的 Q02 空间快照、奖励去重、三模式隔离均通过回归。
- 有对应的真实测试与清晰的越界申请记录，而不是仅根据目录或编码风格宣称合格。

## 11. 执行与维护

本文件建议保存为 `docs/architecture/ARCHITECTURE_EXECUTION_STANDARD.md`；根目录 `AGENTS.md` 应**在保留现有有效规则的前提下**加入一段置顶摘要：

> 所有 Codex 开发任务必须先读取 `docs/architecture/ARCHITECTURE_EXECUTION_STANDARD.md`。严格按任务卡的模块文件所有权与 allowedPaths 工作；任何未授权的跨模块内部依赖、共享契约／存档 schema／稳定 ID／三模式权限修改必须立即停止并提交规范第 6 节申请，待制作人明确批准后才能继续。当前历史耦合不授权扩大或全量重构。完成后执行差异白名单和回归检查，并停止等待验收。

标准变更仅由制作人批准，采用版本号和单独 ADR 记录原因、受影响模块及迁移计划。**Codex 不得自行削弱或删除本标准及其 AGENTS.md 执行入口。**
