# P0-01A 技术可行性审查

审查日期：2026-10-28（Asia/Shanghai）。范围仅 P0-01；下列未来功能只是风险覆盖，不构成开发承诺。

## 阶段门结论（建立主工程之前）

**有条件通过 P0-01B。** 官方归档存在 Godot 4.7.2 Stable（2026-08-18），有 Windows 标准版与同版本导出模板。GDScript、原生 Resource、Control 容器和独立场景足以表达本次三栋建筑的导航样例；未发现已明确的引擎级架构阻碍。保留原技术基线，不升级或换引擎。审查时机器未在 PATH 或常见安装目录找到 Godot，决定获取官方便携版本到忽略目录 `.tools/`。下载/运行受阻时必须降低交付结论，不把可打开源文件称为已运行。

核实证据：[4.7.2 官方归档](https://godotengine.org/download/archive/4.7.2-stable/)、[4.7.2 发布说明](https://godotengine.org/article/maintenance-release-godot-4-7-2/)。最终实测及阶段门验收结果以 [TEST_REPORT.md](TEST_REPORT.md) 为准。

## 可能导致重大返工的边界

1. **构图与输入**：PC 用横向地图区域，手机用纵向建筑排列；同一 ID 与坐标数据经独立布局映射，不能用整幅画面非等比拉伸。1280×720 / 360×780 为各自设计基准。容器分配文字/热点空间，安全区以设备坐标转换为逻辑坐标；必须另做真机触摸、刘海和后台恢复。
2. **空间表现**：先 2D 分层；家具视角、遮挡组合与动画一旦进入量产再改 3D 会造成高额美术返工，因此在房间量产前用最小原型作决定。
3. **状态边界**：建筑导航只识别 ID 与场景，玩法在独立场景内；当前不引入复杂存档。首次持久化前确定版本迁移。
4. **内容隔离**：DEMO 与正式版共用主代码库；后续用构建配置和显式资源清单隔离真实打包资产，不能只隐藏入口。当前只有技术样例，无正式资产，不先建立发布流水线。
