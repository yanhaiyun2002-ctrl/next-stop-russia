# 找猫 R3.2 与首次强制命名规格

## 已确认覆盖旧稿

- 首次猫咪为西伯利亚森林猫，先在同一 HomeScene 真实出现，跑向四个有合法配置的藏点：床/窗/衣柜/书桌。家具世界标签分别为 `кровать/окно/шкаф/стол`，首次显示俄中双语，重玩以俄语为主、可查中文。
- 点击标签的同一个手势播放俄语并判断正误，答错不罚。答对后猫逐步探头、连续出场并等待点击摸猫，不能瞬移到中央。
- **首次摸猫后的命名是必做步骤**，不再提供“稍后再说”。玩家必须选择建议名字或输入名字，并点击“确认”；确认前不得进入下一个主线任务。
- 猫咪可以长期自由重玩，不设置关卡、体力或答错惩罚。

## 状态与幂等性

```text
FIRST_VISIBLE → RUN_TO_SPOT → HIDING_READY → GUESSING
  → PEEK_EARS → PEEK_FACE → WALK_TO_PET_AREA → AWAIT_PET
  → PET_REACTION → FIRST_PET_REWARDED → NAME_REQUIRED
  → NAME_CONFIRMED → FIRST_MEETING_COMPLETE
```

常规重玩使用同一寻找流程，已命名猫咪不再进入 `NAME_REQUIRED`；完成后可再开一局。

**关键时序：**
1. `cat.pet_reaction_completed` 持久化，发放一次性的首次猫咪贴纸和徽章 (`grantOnce('cat_first_meeting_v1')`)；奖励只由摸猫动作触发。
2. 同一事务或恢复流程设置 `catNamePending=true`，出现命名框。命名框不可用关闭按钮、点遮罩或返回键绕过；可退出整个游戏，下次继续命名。
3. 输入合法名字后持久化 `pet.displayName`、`catNamePending=false`，发送 `cat.name_confirmed`；这才完成 `q01_cat` 并指向首次整理。
4. 如果刷新发生在奖励已落盘、名字尚未保存时：重新显示命名框，不重复播放首次藏猫、不重复发奖、不开放城市。

建议命名输入规则（PROPOSED）：去除首尾空格、不能为空、支持中文/俄文/拉丁文及正常空格、最多 20 个用户可见字符；非法输入在按钮旁提示。为了防止卡住，可以提供 2–3 个预设昵称，但选择后仍需要玩家按“确认”。不强制把历史固定名称「普柳莎」作为默认名字。

## 家具藏点数据绑定

每个有效藏点具有 `spotId`, `roomObjectId`, `labelAnchor`, `hideAnchor`, `clueAnchor`, `exitWaypoints[]`, `foregroundOccluderId`, `vocabId`。镜头切换到 `catFit` 前保存 `homeExplore` 的中心/缩放，返回时恢复。

`window` 是固定建筑构件，不因不是家具实例而失去猫咪藏点资格；床/衣柜/书桌为固定功能锚点上的可换款式家具。更换素材后仍须绑定同一对象 ID 或提供合法的位点配置。

## 边界测试

- 初始猫在画面里可见；四个位置都能被 DEV 强制复现。
- 错误标签不移动猫，不重复播放点击后的成功动画；语音不可用时仍能判题。
- 正确标签但未摸猫退出：不奖励；已经完成摸猫但未命名退出：奖励已有、命名必需、主线未推进。
- 名字为空不可通过；关闭页面重新打开可继续；确认后只触发一次 `cat.name_confirmed`。
- 调整窗口后世界标签与热点保持一致，拖镜头不误触；四个藏点必须始终在可操作视角内。
