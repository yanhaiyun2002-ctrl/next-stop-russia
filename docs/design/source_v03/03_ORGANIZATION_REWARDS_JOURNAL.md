# 整理谜题、每日奖励和手账联动（V0.3）

## 1. 本轮 LOCKED

- 宿舍右侧独立的「整理」入口；不点击行李箱或任何特定家具进入。第一次是主线强制教学，完成后可自由进入每日整理。
- 采用格位、容量和明示的逻辑约束，不做计时、体力扣除或固定升级关卡。
- 每个本地自然日恰有一个固定题面，玩家当天无限重玩；重新打开、刷新、通关后不会随机换题，次日可轮换。
- **奖励 A：每日完成记录＋少量纪念奖励，不存在金币、装修货币或可消费积分。** 重玩不会反复发奖励，也不强迫连续签到。

## 2. 已提供可验证题库

数据文件 `04_ORGANIZATION_TEMPLATES.json`：**1 道首次教学题＋5 道每日题**。目前为原型题库（PROPOSED），供程序接口设计与 QA；通过后可以扩充到更多区域和对象，而不是视作固定关卡线。

所有题目已按照 `fixedBin`、`allowedBins`、`forbiddenTogether`、`capacity` 组合**枚举所有放置方式验证**：

| `puzzleId` | 主题 | 物品数 | 仓位容量 | 合法解数量 |
|---|---|---:|---|---:|
| `org_tutorial_01` | 搬入后整理物品 | 4 | 2 / 2 / 1 | 1 |
| `org_daily_01` | 书桌整理 | 5 | 2 / 2 / 2 | 1 |
| `org_daily_02` | 置物架 | 5 | 2 / 2 / 2 | 1 |
| `org_daily_03` | 抽屉整理 | 5 | 2 / 2 / 2 | **2** |
| `org_daily_04` | 衣物收纳 | 5 | 3 / 2 / 2 | 1 |
| `org_daily_05` | 学习用品 | 5 | 2 / 3 / 2 | 1 |

`org_daily_03` 故意允许两种合法布局，确保程序以条件集合而非唯一截图/数组顺序判题。每天只给出题目池中的**一个**稳定题目，而不是当天分发五道连续关卡。

### 建议运行规则（PROPOSED，面向最终数据合同）

1. 每题的 `bins[]` 包含容量；`items[]` 包含占用格数；`rules[]` 定义位置与两两不相容关系。
2. 玩家可拖拽物品进入仓位，小屏幕须可通过“选物品→选仓位”完成等价操作；提供撤销、重置与提示，不施加时间限制。
3. **随时可重置放置盘面**，但不会清空当天历史完成状态。只有所有物品已放置、容量和全部规则均满足时才允许提交成功。
4. 首次教程通过 Q02 引导；其解法明显，重点是熟悉容量和操作。日常题逐步混入允许仓位与不相容条件，不能把真实推理缩水成简单色彩分类。
5. 日期切换期间若正在玩旧题，允许完成当前题面；下一次从整理主入口进入时才创建当天新题，避免盘面突然重置。
6. 采用确定性日期选择，但为防资源或版本更新导致同一天变题，首次访问时**保存当日选中的题面快照**（或稳定引用一份受版本管理的不可变模板）；同日所有重玩使用它。没有服务器的 DEMO 不声称能够阻止修改本地时钟。

### 误操作与提示

- 容量超标时：即时提示“这个区域已经放不下了”，不要直接吞掉拖拽。放置失败不扣分。
- 逻辑冲突时：显示可读、与相应规则一致的提示；不应揭露未点击的全部解法。
- 建议三级提示：复述规则 → 指出可能冲突的仓位 → 给出一个可执行的下一步；均无需消耗货币。
- 无论是否使用提示，正常完成都可记入每日完成记录。不要用“用了提示就不给奖励”强迫反复试错。

## 3. 奖励规则与账本

| 类型 | 触发 | 数量与含义 | 幂等 Key |
|---|---|---|---|
| 首次整理纪念 | `organization.tutorial_completed` | 一次性「安顿好了」贴纸（PROPOSED） | `org_tutorial_first_v1` |
| 每日完成日志 | 某本地日第一次成功完成当日题 | 在手账日期页盖一枚「整理完成」印章；不是货币 | `org_daily_stamp:YYYY-MM-DD` |
| 每日纪念图鉴 | 累计**3 个不同日期**首次完成（PROPOSED） | 一次性「好习惯的开始」纪念贴纸 | `org_distinct_days_3_v1` |
| 当天重复游玩 | 同日第二次及之后成功 | 显示轻量通关反馈、可复习题目，不新增奖励 | 不调用每日领奖 |

只将“3 个不同日期纪念贴纸”作为合理的轻量默认建议，**不在 DEMO 强制要求连续签到**。没有养成数值、货币、经济入口，也不开放商店。手账纪念贴纸与每日日期印章为两种不同记录；若将来需要减少收藏数量，保留每日记录即可调整图鉴里程碑。

## 4. 手账结构

建议手账至少有三个可读取类别：

- **旅途与剧情**：抵达圣彼得堡、领取报到资料、第一章完成等事件记录。
- **俄语词汇**：在找猫互动中接触/成功辨认的家具名词、俄语文字、中文解释和可用时的朗读操作；不强制每次朗读有音频成功才能登记。
- **纪念与生活记录**：首次猫咪互动徽章/贴纸、首次整理贴纸、每日完成日期印章和可选累计里程碑。

手账不是重新计算奖励的第二个系统，而是读取 `RewardLedger`, `LearnedVocab`, `StoryMilestones`, `DailyCompletionLog` 的展示层。用户删除/切换某项展示不应改变原始事件的领奖历史。

## 5. 反重复领奖与跨天

- 每个奖励使用稳定 `rewardKey` 执行原子化 `grantOnce()`，重复调用是 no-op。
- `DailyCompletionLog` 用完成日期去重，允许同日多次通关但只增加一条记录。
- 打开旧日已存在题面并于新的一日提交成功时：完成显示正常，但**默认不回填成新的日常奖励**，避免跨日同时出现两个“今日”题目；下一次进入分配今日题。
- DEV 可以注入日期模拟器，并使用独立的测试存档；PLAYTEST 正常路径不允许以调试参数修改真实完成记录。

## 6. 不属于本轮范围

体力、付费、装修消费、每日连续签到奖惩、无限实时生成谜题、大型物品空间旋转和复杂仓库管理均不在 DEMO 中开发。
