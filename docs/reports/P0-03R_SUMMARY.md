## 1. 视频实际检查：明确可见与推断分开

实际读取 `docs/references/dorm_visual_reference.mp4`：**512×924、63.7435833 秒**。使用 Windows 本地媒体解码，提取覆盖 0–63 秒的 **28 个最近帧请求**，查看前后两张时间联系表和关键画面；不是凭文件名推测。未取得可靠帧率，未分析音频；请求时间不等于宣称精确解码 PTS。

| 时间段 | 视频明确呈现的特征 | 本轮取舍 |
|---|---|---|
| 0–3、10–15、60–63 秒 | 总体正面看入室内，能见家具顶面、地面与顶上结构；窗框、墙分区和家具群分层，编辑面板在下方。 | 借鉴“环境结构 + 家具群”的空间组织，不复制窗样式、家具或装饰。 |
| 20–38 秒 | 房间风格/背景及编辑选项明显变化。 | 不把换风格误记为同一房间中连续走动，也不开发编辑/购买功能。 |
| 40–46、48–52、56–58 秒 | 较大比例局部画面，顶面/地面仍可见；墙窗、座椅等相对固定 UI 横向位移。右侧可见窗和前景座椅，房间没有整体缩成小盒子。 | 手机先显示中部局部，允许有界横拖；PC 使用宽视野。 |
| 54 秒附近 | 另一个换装界面可见。 | 完全不实现；人物、换装与复杂动画不在本轮。 |

**开发者推断/自主选择：**固定 2D 投影加横向取景，是验证这种观看体验的低成本候选；重复几何窗、墙面分区、顶梁可减少空盒子感。**视频未证明**源游戏使用 2D 或 3D、精确眼高/焦距、手势来源/阈值、惯性、缩放、边界规则或真实尺度。10 逻辑单位阈值和复位按钮是本轮设计，不是从视频“测得”的参数。

取帧采用 [Windows MediaComposition.GetThumbnailAsync](https://learn.microsoft.com/en-us/uwp/api/windows.media.editing.mediacomposition.getthumbnailasync) 的最近帧方式，脚本在 `docs/evidence/p0-03r/extract_reference.ps1`，使用系统 Windows PowerShell 5.1 从项目根目录执行。参考文件 SHA-256、各请求时间和帧尺寸见 `reference_manifest.json`；明确观察/推断见 `reference_observations.json`。视频及派生帧仅保留本地并从 Git 忽略，`docs/.gdignore` 同时阻止其成为游戏资源。没有将参考美术、模型、动画或帧图用于游戏或最终拼图。

仍是 CanvasItem/Control 的固定正面透视：眼高 1.4、距离 12、焦距 1500。横向浏览为**同一投影画布的平移裁取**，所有几何/热点统一平移；不是观察者横向走动的物理相机，也不产生动态视差或改变家具可见面。未倾斜为俯视/等距，未非等比拉伸，未增加 Node3D 或通用相机管理器。

背景结构先绘制，家具/标记继续复用 V 的盒体、深度切片、排序及反向多边形拾取，**本轮未重写遮挡算法**。窗、墙分区、顶梁目前属于背景、没有交互；若未来柱体需要挡住角色，必须另做遮挡合同验证，不能据此宣称已支持。

手机视窗按垂直空间维持较大比例，水平边界同时约束到室内背景可覆盖范围与两端主要家具中心，避免拖过家具后继续看空墙。PC 显示较宽范围，必要时可小幅横移。相机平移不修改世界坐标或家具尺寸，窗口改变时按新范围夹紧取景。顶、地沿横向连续，没有为了展示六面体而强行缩小。

## 3. 手机操作与实际画面

五个常驻按钮为床/书桌/衣柜/复位/测试，均至少 48×48 逻辑单位，位于画布外；测试面板默认收起，原标记换点/前后、换位、横移与参数回放仍可用。V 的原版/适中/紧凑预设及 A/B 保留，显式切到旧预设时恢复旧全景/聚焦；不是第二套主工程。

输入继续只有 touch→mouse 单向模拟。按下后累计位移达到 **10 逻辑单位**、且水平占主导才锁定横拖；竖向越阈值取消点击。横拖一经成立，即使手指移回也不激活家具；抬起清空捕获。布局、外部取景改变取消旧按下，拖动自身的重绘保留当前捕获；没有惯性、缩放、跟随或家具编辑。

360×780 模拟下，左/中/右三视图比例始终约 **1.314**，取景中心（投影设计坐标）范围约 **272.19–956.32**，默认中部 **640**。床投影约 **301×158**、桌 **188×127**、柜 **175×267** 逻辑单位；左右端点检查家具包围范围完整入屏。包围范围不等于整块可点实心区域，细桌腿仍依赖清晰具名按钮作为大目标。

开发者审图意见：手机较 V 全景显著增大家具，顶/地填满浏览区域，PC 的重复窗/墙/顶结构使画面更像一段连续室内，较少“空盒子”。但灰盒仍有较大墙面和简化顶梁，横向尺度是否像宿舍、而不是大开间，仍应由负责人按图确认。当前三家具数量很少，不能凭几何环境承诺正式生活空间体验已经成立。

## 5. 风险、变更与决定点

本轮未验证 Android/iOS 真机触摸、系统手势、安全区/生命周期、macOS 运行或移动性能；没有重建平台包。没有进行原生窗口手工拖动或真人体验测试，只审看真实渲染与合成输入证据。10 单位阈值、横向意图锁定、具名按钮与复位的易用性仍待真人/真机确认。

边界与结构为三个样例服务；增加家具、移动柱体遮挡、旋转、透明、动画或动态视差需新验证。固定投影平移保证当前连续性，但不能宣称物理侧移透视正确。PC 在最宽比例横移范围很小，符合当前宽视野，不代表通用大地图摄像机已建成。

产品代码只修改 `scripts/dormitory/{dormitory,room_view,room_world}.gd`；新输入分支与 R 房间数据是局部实现，V 的面切片/排序/拾取复用。新增 `tests/ribbon_tests.gd`（及 UID）与 `ribbon.ps1`，两份旧套件增加 V fixture 初始化，工程规则/README/基线范围/风险/ADR 更新本轮说明。**地图、学校、商店、导航、BuildingDefinition、project.godot 未改。** 无正式美术、装修/购买、找猫、整理、剧情、NPC、俄语、换装、复杂动画、完整 3D、联网、存档或 WorkBuddy 资源。

建议将“横向连续空间 + 手机大比例浏览”保留为更接近参考体验的候选；不建议退回默认整房缩小。负责人需确认：房间宽度与家具间距是否自然；顶面/窗分区是否过密；默认中部及两端范围是否合适；10 单位阈值与点击仅反馈是否可接受；是否需要未来视差（当前不实现）。这些是待确认项，不是本轮自动扩展需求。
